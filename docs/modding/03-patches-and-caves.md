# Existing patches and C caves

Part of the [modding knowledge base](README.md). Our own analysis of NCAA Football 14 (PS3, BLUS31159) and the CFB Revamped v21 base: names, addresses, table layouts and how our mods are built. Source tags in brackets (for example TEA, CFBR) refer to private working notes that are not published; treat each statement as a compiled finding, not a re-verified fact. No game files, extracted assets or decompiled code are included.

## 3. Existing patches and caves

### 3.0 Identity facts every patch depends on

- Two executables are patched, with different PPU keys and address spaces:
  - STOCK 1.00 ELF sha256 a486a9467c740637892df1fc407d8fea9d92d83cf11ff0de3fe464f934e47abe; RPCS3 PPU key PPU-011a5e6caad2e7361265a9a230cf385f805671fb; patch version tag [01.00]. 31 patch.yml files in patches/ use it. [patches/*/patch.yml header; ps3recomp-spike.md]
  - CFBR v21 / update 1.02 ELF (decrypted) sha256 144dee9040da9cb1e8337844fbb685a0f06e560b8fee8d9ba1eac87b9e300c1c; PPU key PPU-62e25ebc1957382b34f2778554943e40d6d84e3c; tag [01.02]. 24 patch.yml files use it. [patches/*/patch.yml header; cfbr-integration.md]
- CFBR's ELF is NOT stock+patches: globals sit at stock + 0x10080, code is reshuffled, every patch had to be re-mapped. [pc-modded-build.md; cfbr-port.md]
- None of the 517 stock expansion preimages matched at their old addresses in the CFBR ELF; a mapping port (3.66M anchor pairs, difflib per function) produced the cfbr-* patches. [cfbr-integration.md; cfbr-port.md]
- All patch.yml files use only `[be32, 0xADDR, 0xWORD]` entries (no calloc/jump/jumpl/jumpf) in the CFBR line. [pc-modded-build.md section 1b]
- Manifests record `runtime_tested: false` for the cfbr-* patch packages (static flag at build time). Runtime acceptance evidence for the stacked stages lives in other docs (section 3). [patches/cfbr-*/manifest.json; continuation-checkpoint.md]


### 3.1 Patch format, application on RPCS3, and full inventory

#### 1.1 How patches are applied on RPCS3 (PPU patch YAML)
- Format (generated by builders; checked by scripts/check_patch_yaml.py): (V) [patches/cfbr-*/patch.yml]
  ```
  Version: 1.2
  PPU-<hash>:
    <Title>:
      Games:
        NCAA Football 14:
          BLUS31159: [01.02]
      Author: Local NCAA14 project
      Notes: ...
      Patch Version: ...
      Patch:
        - [be32, 0x00539ae0, 0x2c03003d]
  ```
  A separate `patch_config.yml` (5 lines) enables the title under the same PPU key / game / serial. [patches/cfbr-picker-order-v2/patch_config.yml]
- Installed copies: runtime/patches/patch.yml and runtime/config/patch_config.yml (per profile). Installers refuse to run if these differ from the stock baseline kept at patches/preference-integration/runtime-backup. [install_cfbr_real2026.ps1 header; cfbr_real2026_runtime_v26.py]
- Loader pitfalls found:
  - yaml-cpp failure: an unquoted ": " in a plain Notes scalar made RPCS3 silently skip the whole patch file ("PAT: Failed to load patch file ... illegal map value", playoff v3, combined v5 run, 2026-10-10). Gate: scripts/check_patch_yaml.py checks tabs, indent, ": " and " #" in plain scalars, and exact `- [be32, 0xAAAAAAAA, 0xWWWWWWWW]` lowercase 8-digit shape. [check_patch_yaml.py docstring; continuation-checkpoint.md lines 866-880]
  - Boot gate: scripts/check_patch_applied.py reads the live RPCS3 log for `PAT: Applied patch (... description='<title>' ...) (<- N)` per expected title; `--expect-count "TITLE=N"` (N counts entries actually written; an entry whose address does not translate is skipped silently, only a smaller N shows it). `--expect-calloc` exists for calloc. [code-room-and-news-fix.md 1.2; installer v10 header]
- RPCS3 patch types (installed build v0.0.43-20250-304d544b, 2026-10-08): `be32`/others, `calloc` (allocates a 64 KB-aligned executable block, writes N words in order, addresses ignored), `jump`/`jumpl` (host-side far jump, guest word unchanged), `jumpf`, `alloc` (fixed-address zeroed scratch; be32 writes into it fail translation). Only be32 is used by shipped patches. [code-room-and-news-fix.md 1.1-1.2]
- Code room used: the SEGMENT-0 TAIL = bytes between the end of PT_LOAD segment 0 and the next 64 KB boundary. RPCS3 maps them executable and lets plain be32 patches write them. Stock: 3,840 B (960 words) at 0x1bbf100..0x1bc0000. CFBR: 55,552 B (13,888 words) at 0x1bc2700..0x1bd0000 (p_filesz ends 0x1bc26e8 on CFBR; log shows p_filesz=0x1bb26e8 p_memsz=0x1bb26e8 for the first-segment table entry of the stock-style listing; treat exact stock tail numbers as in the doc). `calloc` is the fallback, predicted address 0x1d60000 stock / 0x1d70000 CFBR (UNVERIFIED, marked [INF] in source). [code-room-and-news-fix.md bottom line, 1.3, 1.4; pc-modded-build.md]
- Other code room used by earlier caves: proven-dead stock ranges (call-graph proof), e.g. R2 [0x459b34,0x459e24) for fix U; stock playoff cave = dead BCS tie-in filler 0x459e24..0x45a618 (proof analysis/playoff/cave-proof.json); CFBR playoff cave region [0x45ad9c,0x45b590) is the image of the same filler, single referencing branch = disable site 0x45b7bc. [c-cave-toolchain.md section 4; continuation-checkpoint.md line 975; cfbr-port.md]

### 3.5 C-cave toolchain


2.1 Tools
- Toolchain: zig 0.16.0 (clang 21.1.0, LLD 21.1.0) in the project tools folder, run `python -m ziglang`. [c-cave-toolchain.md; toolchain-check.json; continuation-checkpoint.md 1092]
- scripts/build_c_cave.py (434 lines), tools/ppc-cave/cave.h, scripts/ppc64_mini_emu.py (64-bit integer subset interpreter; no FP/VMX), scripts/check_c_cave_toolchain.py (report analysis/c-cave/toolchain-check.json), playoff_ppc.Cpu (older emulator; lacks lwa/extsw/cntlzw). No README in tools/ppc-cave (only cave.h and docs). [dir listing; c-cave-toolchain.md]

2.2 Write -> build -> verify -> install
1. Write freestanding C `#include "cave.h"`; first function marked CAVE_ENTRY (placed at --base); game functions declared `extern` and given by `--defsym name=0xADDR` (CODE ENTRY, never the OPD); EA-SQL queries via EA_QUERY(GAME_STR(0x17....), &out, in...) -> calls 0xa67320 with r3=r4=r5=0, r6=query; returns 0 if row found, nonzero (0x17 seen) if none; query tags are stored reversed in the ELF strings; fixed game memory through GAME_U32(addr) etc. (cheapest: lis+disp). [c-cave-toolchain.md section 1; cave.h]
2. Build: `python scripts/build_c_cave.py SRC.c --base 0xBASE --end 0xEND --defsym ea_query=0xa67320 [--syms game_syms.json] [--name N] [--out DIR] [-O s] [--list] [--force] [--keep-call-nops]`. Outputs (default tools/ppc-cave/build/<name>/): NAME.words.txt, NAME.manifest.json (addr->word, function addrs/sizes, data syms, defsyms, cflags, rewrite stats, source sha256, tool versions), NAME.patch-lines.txt (`      - [be32, 0x........, 0x........]`), NAME.lst. Output is create-only. Python API: build_c_cave.build(sources, base, end, defsyms, name=, opt='-O2') -> dict(words, functions, data). [c-cave-toolchain.md]
3. Compile flags: --target=powerpc64-unknown-unknown -mabi=elfv1 -mcpu=970 -mno-altivec -mno-vsx -O2 -ffreestanding -fno-builtin -nostdlib -fno-jump-tables -fno-asynchronous-unwind-tables -fno-unwind-tables -fno-exceptions -fno-stack-protector -fno-common -fno-pic -falign-functions=4 -falign-loops=4 -mcmodel=medium. (-mcpu=cell rejected by LLVM; 970 is closest.) [c-cave-toolchain.md section 2]
4. Asm rewrite between `clang -S` and `clang -c` makes the cave TOC-independent: remove .opd and move symbols to code labels; `addis rX,2,S@toc@ha` -> `lis rX,S@ha`, `@toc@l` -> `@l`; drop traceback stubs; drop TOC-restore nop after each bl. Refuses if any @toc/@got/@plt/TLS/.opd reference survives. [c-cave-toolchain.md]
5. Link: lld `-static --no-undefined` with generated linker script: .text.entry, .text*, .rodata*, .toc into CAVE (rx) [base,end); every other allocated section -> FORBID region that must stay empty. [c-cave-toolchain.md section 3]
6. Post-link guard (enforced): no relocs other than ADDR64/32, ADDR16_LO/HI/HA/LO_DS, REL24, REL14, REL32/64; no writable .data/.bss/.sdata; no thunks; every opcode known (no VMX, sc, traps); NO instruction reads/writes r2; no absolute branches; every b/bc target inside cave; every bl target inside cave or exactly a --defsym; mtspr/mfspr only LR/CTR/XER. Negative tests (all rejected for the expected reason): writable global, function-pointer call (std r2,40(r1)), call 0x3000000 away (long-branch thunk), undefined symbol, cave overflow ("will not fit in region CAVE", overflowed by 76 bytes in test), hand-written lwz r3,-0x7ff0(r2). [c-cave-toolchain.md; toolchain-check.json guard_negatives]
7. Feed builders: builders work in (addr, preimage, new word) triples; assert preimage against pinned ELF; `put('cave', [(a, word(a), w) for a, w in r['words']])`; site words stay hand-encoded (bl()/li/address repoints). Entry address = r['functions'][name]['addr']. [c-cave-toolchain.md section 4]
8. Gates: scripts/check_patch_yaml.py on every patch.yml (`--all` allowed); keep Notes free of ": " or quote; emulation against a model (ppc64_mini_emu), preimage asserts on every site word, then install via the stage installer and the boot gate (check_patch_applied.py --expect-count). Reproducibility: manifest pins clang version, cflags, source sha. [c-cave-toolchain.md; code-room-and-news-fix.md]

2.3 Constraints / known limits
- ABI: 64-bit ELFv1 (callees may spill r3..r10 into caller param save area 48..112(r1); frames >=112 bytes; N multiple of 16); r13 never touched; r2 (game TOC) never touched; no mutable cave state (no .data/.bss; use game memory or stack); no function pointers/vtable calls through clang (use inline mtctr/bctrl asm that never touches r2, as modern_ot.c does); no libc (memcpy/memset become undefined symbols); LP64 pointers vs 4-byte game pointers (use gptr); bl range +-32 MB. [c-cave-toolchain.md sections 2, 6]
- Entry only at call sites: C may clobber all volatiles; drop-in only where patched word is already a `bl` or live volatiles are dead; mid-block hooks need a few hand-written shim words (save regs, bl body, restore). [c-cave-toolchain.md section 6]
- Code-size: -O2 same as hand for query helpers (SW 17 vs 17); larger routines grow; use -O s. lld pads with trap words 0x7fe00008 (never executed). [c-cave-toolchain.md]
- Emulation coverage: SW C vs hand equal across 15 query outcomes on both emulators; features.c matches Python model on 60 randomized runs; cfp_news_fix: 48 gates per ELF, 2,408 emulated scenarios. [toolchain-check.json; code-room-and-news-fix.md]
- Segment-0 tail build for CFBR: `--base 0x1bc2700 --end 0x1bd0000`. A tail cave extends p_filesz/p_memsz of segment 0 on the PC build (section 6). [code-room-and-news-fix.md 1.4; pc-modded-build.md]
- Recommended future C use: playoff toggles, transfer portal (new logic); roster size is mostly constants not C; recruit names are data. Needs a bigger dead region and port of checks to ppc64_mini_emu. [c-cave-toolchain.md section 7]
- Summary of toolchain-check.json keys: tools, sw_equivalence (passed, hand_words 17, c_words 17, word-level diffs are scheduling only), feature_probe (passed, 60 runs), guard_negatives (6 cases rejected), yaml_gate (passed, no problems), passed true. [analysis/c-cave/toolchain-check.json]
